
Audit Objective :-

The audit objective in the approved 2026 audit plan was:

• To assess the governance and control effectiveness of agent network management including sales steering and target setting; sales support and administration; remuneration and incentive schemes; and sales excellence, recruitment and training. The audit will focus on Independent Financial Advisor (IFA) management.

The audit will be performed as a catalogue audit.

The audit object, per the Master Audit Universe is Agent Network Management including Contact Management.

The audit work will encompass interviews with appropriate management and other staff members, as well as the review of processes and respective key documentation to assess the design and effectiveness of in scope processes and internal controls. The performance or outcome of the respective key processes and controls will be verified by means of operating effectiveness or substantive testing.

Risk :- Non-existing, Incomplete, or Non-compliant Policies, Standards and Functional Rules.

Control :- Gov 3b_Operational Structure Documentation and Procedural Knowledge / Content Expertise.

Control description:- Up-to-date documentation of operational structure (e.g., Corporate Rules/Policies, Adonis/Process descriptions, etc.)


1. Restated Risk
The risk is that policies, standards, and functional rules governing agent network management — specifically IFA management — either do not exist, are incomplete in their coverage of required subject matter, or fail to comply with applicable regulatory or internal requirements. The failure pathway is a governance-layer gap: absent or deficient foundational documentation leaves the IFA agent network without enforceable standards for sales steering, target setting, remuneration, recruitment, training, and related processes, exposing the organization to uncontrolled conduct risk and potential regulatory non-compliance.

The risk contains three distinct failure modes: (a) non-existence, (b) incompleteness, and (c) non-compliance of the governing documents.

2. Restated Control Description
The control description states: "Up-to-date documentation of operational structure (e.g., Corporate Rules/Policies, Adonis/Process descriptions, etc.)"

As written, this is a statement of a desired condition — that documentation exists and is current — rather than a description of a control activity. No actor is named. No action verb describes what is performed. No trigger event or review frequency is stated. No escalation or remediation path is described. The parenthetical examples are open-ended ("e.g." and "etc."), leaving the scope of documentation unbounded. The control name references "Procedural Knowledge / Content Expertise," but the control description does not address procedural knowledge or content expertise in any way.

3. Mitigation Assessment
Rating: Does Not Mitigate

The control description fails to map onto any of the three failure modes in the stated risk for the following reasons:

Non-existence of policies/standards: The description asserts that documentation exists but does not describe any mechanism — such as a periodic inventory, gap analysis, or governed document register — that would detect or prevent the absence of required policies.
Incompleteness of policies/standards: No assessment, review cycle, or completeness criteria are described. There is no mechanism to determine whether existing documentation covers all required subject-matter areas for IFA management.
Non-compliance of policies/standards: No compliance-review step, regulatory mapping, or sign-off process is described. There is no mechanism to verify that documentation meets applicable regulatory or internal requirements.
The control description operates in the same topical area as the risk (governance documentation), but asserting a desired state is not the same as describing a control that achieves or maintains that state. A control must describe an action that interrupts or detects the risk's failure pathway; this description does neither.

Additionally, the control name's reference to "Procedural Knowledge / Content Expertise" is entirely unaddressed by the control description — this represents a scope-mismatch issue where the control identifier implies broader coverage than the description delivers.

4. Control Type Consideration
The control description does not describe a mechanism that can be classified as either preventive or detective. If interpreted charitably as a preventive control (maintaining current documentation to prevent governance gaps from arising), no maintenance activity, responsible party, or update trigger is described. If interpreted as a detective control (periodic review to identify documentation gaps), no review frequency, reviewer, criteria, or escalation path is stated. Given that the risk addresses the foundational existence and adequacy of governance documents, a preventive mechanism (governed document lifecycle with defined ownership, periodic review, and regulatory-mapping requirements) would be more appropriate than a purely detective one — but neither type is discernible from the current description.

5. Specificity Assessment
The control description is insufficiently specific to be assessable as a mitigation mechanism. The following required elements are absent:

Named actor: No individual or role is identified as responsible for creating, reviewing, approving, or maintaining the documentation.
Defined action: No verb describes a control activity being performed. The description is a noun phrase ("up-to-date documentation"), not an action statement.
Trigger or frequency: No event trigger or periodic schedule is stated. "Up-to-date" implies currency but does not define how currency is maintained or verified, or at what interval.
Bounded scope: The use of "e.g." and "etc." leaves the population of documents undefined. An assessor cannot determine what documentation should exist, and therefore cannot determine whether it does exist.
Output or escalation: No defined outcome, exception process, or remediation path is described for instances where documentation is found to be missing, incomplete, or non-compliant.
Independent of the mitigation-adequacy finding above, the description as written would not support a design-effectiveness test because there is no testable control activity to evaluate.

6. Verdict
Does Not Mitigate. The control description is a condition statement asserting a desired state, not a description of a control mechanism. It does not identify an actor, action, trigger, or frequency, and it does not address the incompleteness or non-compliance failure modes of the risk.

7. Suggested Refinements
To close the gap, the control description would need to be revised to include, at minimum:

A named actor or role (e.g., Head of IFA Management, Compliance Officer, Policy Owner) responsible for the control activity.
A defined action describing what is performed — such as maintaining a governed policy register, conducting a periodic completeness review against a defined policy inventory, or performing a regulatory compliance mapping exercise.
A stated trigger or frequency — for example, annual review cycle, triggered upon regulatory change, or upon material change to the IFA operating model.
Completeness criteria — a defined inventory or framework specifying what policies, standards, and functional rules are required to govern IFA agent network management.
A compliance-verification step — describing how existing documentation is assessed against applicable regulatory and internal requirements.
A bounded scope — replacing "e.g." and "etc." with a defined population of documents or a reference to a maintained register.
Alignment between the control name and description — if "Procedural Knowledge / Content Expertise" is within scope, the description must address how procedural knowledge and content expertise are maintained, verified, or evidenced.
These are description-level refinements. They do not prescribe redesign of the underlying business process, but the current description does not contain enough substance to constitute a control statement.

8. Open Questions for the Auditor
Is there an underlying control activity that this description is intended to summarize? If a defined review cycle, policy owner, or governance framework exists in practice but was not captured in the RACM description, the description should be rewritten to reflect the actual mechanism. If answered unfavorably (no underlying mechanism exists), the verdict remains Does Not Mitigate and the finding escalates from a documentation gap to a control-design gap.
Does this control operate in conjunction with other controls that jointly address the three failure modes of the risk? If so, the partial-coverage gap may be mitigated at the risk level by the full control set, but this individual control's description would still require refinement to describe a testable mechanism. If answered unfavorably (this is the sole control for the risk), the risk is unmitigated.
What is the intended scope of "Procedural Knowledge / Content Expertise" referenced in the control name? If this element is meant to be assessed under this control, the description must be expanded. If it is addressed by a separate control, the control naming may need clarification to avoid confusion during testing.
9. Methodology Compliance & References
The uploaded methodology document (Allianz UK SAM v2) was consulted for control-design adequacy criteria. The document could not be accessed with sufficient specificity to confirm whether it defines explicit standards for what constitutes an adequate control description in design-assessment terms. Accordingly, this assessment draws on general IA practice — specifically the principle that a control must describe a named actor performing a defined action at a stated frequency or trigger, and that the control's action must map to the specific failure pathway of the risk it purports to mitigate. This is consistent with IIA Standards and COSO Internal Control framework principles regarding control-activity design. This reliance on general practice is explicitly noted.

10. Gate Status
Gate 1: Not Passed. The control description does not describe a control mechanism and cannot be assessed as mitigating the stated risk. Gate 2 (DET/OET review) is not yet available in this tool.
